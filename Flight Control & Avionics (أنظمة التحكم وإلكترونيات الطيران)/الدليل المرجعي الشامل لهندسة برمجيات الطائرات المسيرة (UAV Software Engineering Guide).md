## 1. المعمارية البرمجية للطائرة المسيرة (UAV Software Stack Architecture)

تنقسم المنظومة البرمجية داخل الطائرة المسيرة الاحترافية إلى طبقتين فيزيائيتين وبرمجيتين تتواصلان فيما بينهما باستمرار:

* **الطبقة الدنيا - متحكم الطيران (Low-Level Flight Controller - Hard Real-Time):**
  تعمل هذه الطبقة على متحكمات دقيقة عالية الموثوقية (مثل معالجات ARM Cortex-M7 كشريحة STM32H7) فوق نظام تشغيل في الزمن الحقيقي (**Real-Time Operating System - RTOS**) مثل NuttX أو ChibiOS. تتولى هذه الطبقة قراءة المستشعرات، تشغيل مرشحات تقدير الحالة، وحساب حلقات التحكم (**PID**) لإرسال إشارات السرعة للمحركات بترددات صارمة تتراوح بين 400Hz و8000Hz، حيث يؤدي أي تأخر زمني بأجزاء من الثانية إلى فقدان التوازن.

* **الطبقة العليا - الحاسوب المرافق (High-Level Companion Computer - Soft Real-Time):**
  تعمل هذه الطبقة على حواسيب مدمجة أحادية اللوحة (مثل Raspberry Pi أو NVIDIA Jetson) فوق نظام تشغيل Linux. تتولى هذه الطبقة المهام كثيفة الحوسبة التي لا يتطلب تنفيذها تزامناً بالميكروثانية، مثل معالجة الصور، تفادي العوائق، بناء الخرائط الآني (**Simultaneous Localization and Mapping - SLAM**)، وإدارة قرارات السرب بترددات تتراوح بين 10Hz و60Hz.

## 2. الخريطة التقنية للغات البرمجة ومواضع استخدامها (Programming Languages Architecture)

لا تُبرمج الطائرة المسيرة بلغة واحدة، بل تُوظف كل لغة في الموضع الذي يتوافق مع خصائصها في إدارة الذاكرة وسرعة التنفيذ:

| اللغة البرمجية | الطبقة المعمارية | الوظيفة الهندسية | الأنظمة والمكتبات | مستوى الإلزام |
|:---|:---|:---|:---|:---|
| **C / C++** | الدنيا والوسطى | التحكم وتقدير الحالة | PX4, ArduPilot, Eigen | أساسي إلزامي |
| **Python** | العليا والأرضية | الرؤية والذكاء الاصطناعي | OpenCV, PyTorch, MAVSDK | أساسي للمهام الذكية |
| **MATLAB / Simulink** | التصميم والمحاكاة | النمذجة وضبط المتحكمات | Aerospace Blockset | متقدم للتصميم |
| **Rust** | الدنيا الحديثة | أنظمة آمنة الذاكرة | Embassy, RTIC | مستقبلي واعد |
| **Bash / CMake** | البناء والتشغيل | الترجمة وأتمتة العقد | GCC, Ninja, Docker | ضروري للبيئة |

تُهيمن لغة **C++** على برمجة متحكم الطيران لأنها تترجم مباشرة إلى لغة الآلة وتمنح المبرمج تحكماً مطلقاً في عناوين الذاكرة؛ إذ لا تحتوي على جامع قمامة (**Garbage Collector**) قد يوقف المعالج فجأة لتنظيف الذاكرة أثناء الطيران. في المقابل، تتفوق لغة **Python** في الحاسوب المرافق لسرعة كتابة الخوارزميات المعقدة وتوافر مكتبات الرؤية الحاسوبية والشبكات العصبية الجاهزة.

## 3. هندسة برمجة المستشعرات ومعالجة إشاراتها (Sensor Programming & Signal Processing)

لا يفهم المعالج الظواهر الفيزيائية كالتسارع أو الضغط الجوي مباشرة، بل يقرأ قيماً رقمية خام (**Raw Bytes**) من سجلات الذاكرة الداخلية للمستشعرات عبر أربعة بروتوكولات اتصال عتادية رئيسية:

* **بروتوكول SPI (Serial Peripheral Interface):** ناقل متزامن فائق السرعة (يصل إلى 20MHz) يُستخدم حصرياً لربط وحدات القياس العطالي (**Inertial Measurement Unit - IMU** كشريحة ICM-42688) لقراءة الجيروسكوب ومقياس التسارع بآلاف المرات في الثانية.
* **بروتوكول I2C (Inter-Integrated Circuit):** ناقل من سلكين بسرعة متوسطة (400kHz) يُستخدم للمستشعرات ذات التردد المنخفض مثل البارومتر (حساس الضغط الجوي للارتفاع) والبوصلة المغناطيسية الخارجية.
* **بروتوكول UART (Universal Asynchronous Receiver-Transmitter):** اتصال تسلسلي مباشر يُستخدم لاستقبال حزم البيانات المستمرة من وحدات تحديد الموقع (**GPS**) وحساسات التدفق البصري (**Optical Flow**).
* **بروتوكول DroneCAN:** شبكة صناعية مقاومة للتشويش الكهرومغناطيسي الناتج عن أسلاك الطاقة، تُستخدم في الطائرات المتقدمة لربط وحدات التحكم بالسرعة الذكية (**Electronic Speed Controllers - ESCs**) ومستشعرات الهواء.

تتم برمجة المستشعر بلغة **C** أو **C++** عبر ثلاث مراحل برمجية متتالية داخل متحكم الطيران:

1. **الاستحواذ المباشر عبر الذاكرة (DMA Acquisition):** يكتب المبرمج تعريفاً (**Device Driver**) يأمر وحدة الوصول المباشر للذاكرة (**Direct Memory Access - DMA**) بسحب القراءات من منفذ SPI ووضعها في مصفوفة بالذاكرة تلقائياً دون إشغال المعالج الرئيسي.
2. **التصفية الرقمية (Digital Filtering):** تمر القراءات الخام عبر مرشحات برمجية مكتوبة بلغة C++ مثل مرشح التمرير المنخفض (**Low-Pass Filter**) ومرشح القمع الديناميكي (**Dynamic Notch Filter**) لحذف الضجيج الناتج عن اهتزاز المراوح.
3. **دمج المستشعرات وتقدير الحالة (Sensor Fusion via EKF):** ينحرف الجيروسكوب مع الوقت، بينما يعاني الـ GPS من البطء؛ لذا تُدمج قراءاتهما معاً داخل خوارزمية **مرشح كالمان الممتد (Extended Kalman Filter - EKF)** المكتوبة بلغة C++ لإخراج زاوية وموقع الطائرة بدقة لحظية.

## 4. هندسة دمج اللغات البرمجية وبروتوكولات التخاطب (Multi-Language Integration)

عند بناء طائرة مسيرة ذكية، ستكتب خوارزمية الرؤية الحاسوبية بلغة **Python** على حاسوب Raspberry Pi، بينما يعمل كود التوازن بلغة **C++** على متحكم الطيران (مثل Pixhawk). يتم دمج اللغتين وجعلهما يتخاطبان لحظياً عبر إحدى الطرق الهندسية الثلاث التالية:

### الطريقة الأولى: بروتوكول MAVLink عبر الوصلات التسلسلية أو الشبكية

يُعد **MAVLink** لغة التخاطب القياسية في عالم المسيرات، وهو بروتوكول يحول الأوامر البرمجية إلى حزم بايتات مضغوطة جداً تنتقل عبر سلك UART أو شبكة UDP محلية بين اللغتين.

فيما يلي مثال تطبيقي يوضح كيف يرسل كود **Python** أمر تحرك مبني على الرؤية الحاسوبية، وكيف يستقبله وينفذه كود **C++** داخل متحكم الطيران:

<div dir="ltr" align="left">

```python
# الطبقة العليا (Python): يشتغل على الحاسوب المرافق ويرسل أوامر السرعة عبر MAVSDK
import asyncio
from mavsdk import System
from mavsdk.offboard import VelocityBodyYawspeed

async def run_autonomous_mission():
    drone = System()
    await drone.connect(system_address="serial:///dev/ttyAMA0:921600")

    await drone.action.arm()
    await drone.offboard.set_velocity_body(VelocityBodyYawspeed(0.0, 0.0, 0.0, 0.0))
    await drone.offboard.start()

    # أمر التقدم للأمام بسرعة 2 متر/ثانية والارتفاع للأعلى بسرعة 0.5 متر/ثانية
    await drone.offboard.set_velocity_body(VelocityBodyYawspeed(2.0, 0.0, -0.5, 15.0))
    await asyncio.sleep(5)

asyncio.run(run_autonomous_mission())
```

</div>

في الطرف الآخر، يستقبل نظام الطيران المكتوب بلغة **C++** هذه الحزمة عبر نظام النشر والاشتراك الداخلي (مثل `uORB` في نظام PX4) ويحولها إلى إشارات للمحركات:

<div dir="ltr" align="left">

```cpp
// الطبقة الدنيا (C++): جزء مبسط من حلقة التحكم داخل نظام PX4 يستقبل الأمر وينفذه
#include <uORB/topics/vehicle_local_position_setpoint.h>

void FlightController::process_offboard_commands() {
    vehicle_local_position_setpoint_s setpoint;
    
    // فحص وصول حزمة جديدة من كود البايثون عبر جسر MAVLink
    if (_setpoint_sub.update(&setpoint)) {
        float target_vx = setpoint.vx; // 2.0 m/s
        float target_vz = setpoint.vz; // -0.5 m/s
        
        // تمرير السرعات المطلوبة إلى متحكم PID لحساب دفع المحركات
        _velocity_pid.setGoal(target_vx, setpoint.vy, target_vz);
        _motor_mixer.outputPWM(_velocity_pid.calculate(dt));
    }
}
```

</div>

### الطريقة الثانية: إطار عمل الروبوتات (ROS 2 & uXRCE-DDS)

يوفر نظام **ROS 2** بيئة موحدة تسمح بكتابة برنامج مكون من عدة ملفات (**Nodes**) بلغات مختلفة تماماً. يمكنك كتابة عقدة لمعالجة بيانات الرادار الليزري (**LiDAR**) بلغة **C++** لسرعتها الفائقة، وعقدة أخرى لتحليل صورة الكاميرا بنموذج YOLOv8 بلغة **Python**؛ وتتواصل العقدتان مباشرة عبر قنوات تسمى (**Topics**) باستخدام بروتوكول DDS دون الحاجة لكتابة أي كود ترجمة بينهما.

### الطريقة الثالثة: تغليف دوال C++ داخل Python (Pybind11)

إذا كنت تكتب برنامجاً بلغة Python على الحاسوب المرافق، وواجهت معادلة رياضية لتخطيط المسار تستهلك وقتاً طويلاً في بايثون، يمكنك كتابة هذه المعادلة تحديداً بلغة **C++**، ثم ترجمتها كملف مكتبة مشتركة (`.so` في لينكس) واستدعائها داخل ملف البايثون كأنها دالة بايثون عادية باستخدام مكتبة **Pybind11**.

## 5. ترسانة الأدوات البرمجية لمهندس الطائرات المسيرة (Developer Toolchain)

لا يكتب مهندس الطائرات المسيرة الكود من الصفر في كل مرة، بل يعتمد على حزمة أدوات صناعية قياسية لتطوير واختبار الأنظمة بأمان:

* **أنظمة الطيران مفتوحة المصدر (Flight Stacks):** يتصدر المشهد نظاما **PX4 Autopilot** (المتميز بمعماريته الحديثة وتكامله المباشر مع ROS 2) و**ArduPilot** (المتميز بدعمه الهائل لمختلف الشرائح واستقراره الميداني).
* **المحاكاة البرمجية في الحلقة (SITL Simulation):** أداة تتيح تشغيل كود الطائرة الحقيقي (C++) على حاسوبك الشخصي وربطه بمحاكي فيزيائي ثلاثي الأبعاد مثل **Gazebo** أو **Webots** لاختبار الكود والتثبُّت (**Verification**) من سلامته قبل المخاطرة بتحطيم طائرة حقيقية.
* **محطات التحكم الأرضي (Ground Control Stations):** برامج مثل **QGroundControl** و**Mission Planner** تُستخدم لضبط معاملات الطائرة (**Configuration Management**)، مراقبة الحساسات لحظياً، وتحميل البرمجيات.
* **أدوات تحليل سجلات الطيران (Log Analyzers):** برامج مثل **PlotJuggler** تُستخدم بعد الهبوط لتحليل ملفات السجل (`.ulg` أو `.bin`) وكشف أخطاء التتبع في حلقات PID أو تشبع الإشارات بالرسم البياني.

## 6. المسار التدريبي المجاني والمصادر المعتمدة للاحتراف (Academic & Technical References)

تجمع القائمة التالية أقوى المقررات الجامعية والأدلة الهندسية المجانية بالكامل، مرتبة حسب التخصص الدقيق:

### أ. تأسيس لغة C++ والأنظمة المدمجة (Embedded Systems & RTOS)
* **[LearnCpp.com](https://www.learncpp.com/):** المرجع النصي الأفضل عالمياً لإتقان لغة C++ الحديثة من الصفر وحتى إدارة الذاكرة والمؤشرات والبرمجة الكائنية.
* **[Modern Embedded Systems Programming (YouTube)](https://www.youtube.com/playlist?list=PLPW8O6W-1chwyTzI3BHwBLbGQoPFxPAPM):** دورة عملية مجانية تشرح برمجة معالجات ARM Cortex-M على مستوى السجلات (**Registers**)، المقاطعات (**Interrupts**)، وأنظمة التشغيل اللحظية (**RTOS**).

### ب. تأسيس لغة Python والرؤية الحاسوبية (Python & Computer Vision)
* **[Harvard CS50’s Introduction to Programming with Python](https://cs50.harvard.edu/python/):** مقرر جامعة هارفارد المجاني لتأسيس عقلية برمجية صلبة في لغة بايثون وكتابة أكواد نظيفة.
* **[OpenCV University Free Courses](https://opencv.org/university/free-courses/):** الدورات المجانية الرسمية لمكتبة OpenCV لتعلم معالجة الصور واكتشاف الأجسام للطائرات المسيرة.

### ج. ديناميكا الطيران وهندسة التحكم (Flight Dynamics & Control Theory)
* **[ETH Zurich: Autonomous Mobile Robots](https://asl.ethz.ch/education/lectures/autonomous_mobile_robots.html):** محاضرات المعهد الفيدرالي السويسري المجانية، وتغطي معادلات الحركة، الاستشعار، وتقدير الحالة بمرشح كالمان.
* **[Control Bootcamp - Prof. Steve Brunton](https://www.youtube.com/playlist?list=PLMrJAkhIeNNR20Mz-VpzgfQs5zrYi085m):** سلسلة أكاديمية من جامعة واشنطن تشرح هندسة التحكم الحديثة، استقرار الأنظمة، وتمثيل فضاء الحالة (**State-Space Representation**).
* **[MathWorks MATLAB & Simulink Onramp](https://matlabacademy.mathworks.com/):** دورات تفاعلية مجانية من شركة MathWorks لتعلم نمذجة الأنظمة الفيزيائية وتصميم متحكمات PID في بيئة Simulink.

### د. معمارية أنظمة الطيران والربط الشبكي (PX4, ArduPilot & ROS 2)
* **[PX4 Autopilot Official Developer Guide](https://docs.px4.io/main/en/):** الدليل الهندسي الرسمي لتعلم بناء شيفرة PX4، وتشغيل المحاكي SITL، وكتابة وحدات برمجية جديدة بلغة C++.
* **[ArduPilot Developer Documentation](https://ardupilot.org/dev/):** التوثيق الرسمي لمطوري ArduPilot، ويشرح بنية تجريد العتاد (**AP_HAL**) وكيفية إضافة تعريفات المستشعرات الجديدة.
* **[ROS 2 Official Tutorials](https://docs.ros.org/en/humble/Tutorials.html):** الدليل التطبيقي الرسمي لبناء العقد البرمجية (**Nodes**) والربط بين لغتي C++ وPython في الأنظمة الروبوتية.
* **[MAVSDK-Python Official Documentation](https://mavsdk.mavlink.io/main/en/python/):** التوثيق الرسمي مع أمثلة برمجية جاهزة للتحكم بالطائرات المسيرة برمجياً باستخدام لغة بايثون.

## 7. خطة التنفيذ العملية للانتقال من الصفر إلى الاحتراف (Implementation Roadmap)

1. **المرحلة الأولى (بناء الأساس البرمجي والعتادي):** ابدأ بدراسة أساسيات C++ وPython، وطبق ما تتعلمه عملياً بجلب لوحة تطوير منخفضة التكلفة (مثل STM32 أو ESP32) مع حساس IMU (مثل MPU6050)، واكتب كود C++ يقرأ بيانات الحساس عبر بروتوكول I2C ويطبع زوايا الميلان على الشاشة.
2. **المرحلة الثانية (إتقان لينكس والمحاكاة الفيزيائية):** ثبّت نظام Ubuntu Linux (كبيئة أساسية أو عبر WSL2 في ويندوز)، وقم بتنزيل شيفرة **PX4** وتشغيلها داخل محاكي **Gazebo**؛ لتعتاد على رؤية طائرة افتراضية تطير أمامك وتستجيب للأوامر دون تكلفة مادية.
3. **المرحلة الثالثة (برمجة المهام الذاتية بلغة Python):** اكتب أول سكربت Python باستخدام مكتبة **MAVSDK** يتصل بالطائرة داخل المحاكي، ويأمرها بالإقلاع، والتحليق على شكل مربع هندسي، ثم الهبوط التلقائي.
4. **المرحلة الرابعة (التعديل على نواة الطيران بلغة C++):** افتح الشيفرة المصدرية لنظام PX4 أو ArduPilot، وتعلم كيف تقرأ مخطط تدفق البيانات، ثم أنشئ وحدة برمجية صغيرة (**Custom Module**) بلغة C++ تقرأ بيانات البارومتر وتطبع تنبيهاً عند تجاوز ارتفاع معين.
5. **المرحلة الخامسة (الدمج الكامل عبر ROS 2 والرؤية الحاسوبية):** اربط محاكي الطائرة بنظام **ROS 2**، واكتب عقدة برمجية بلغة Python تلتقط بث الكاميرا من الطائرة الافتراضية، وتكتشف هدفاً ملوناً على الأرض باستخدام **OpenCV**، ثم ترسل أوامر سرعة لحظية إلى متحكم الطيران المكتوب بلغة C++ للهبوط فوق الهدف بدقة.
